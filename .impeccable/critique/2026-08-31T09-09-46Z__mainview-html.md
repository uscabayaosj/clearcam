## Design Specificity Verdict
Authored, not interchangeable — with one glaring seam. The shell, reel, journal, ledger, and household surfaces are written for exactly this product and owner. But Global Settings and the Add Alert builder fall out of the observatory into the engine's own vocabulary (YOLOv9, OpenCLIP, Qwen3VL, raw COCO class grid). The surface is bespoke; the configuration layer is developer tooling wearing the surface's dark paint.

## Priority Issues
1. **[P1] Alert builder speaks COCO, not household.** ~20 raw model classes + three optional sub-forms; the product's core configuration task requires ML literacy. Fix: "Common" group (person/car/cat/dog) + collapsed "More object types"; render the composed rule as a live sentence above Save. → $impeccable distill + clarify
2. **[P1] Storage-limit warning severed from its remedy.** Highest-stakes state on the surface rendered as unaccented prose; the fix hides in a collapsed disclosure. Fix: brass-accented status treatment + inline "Adjust storage limit" action that opens and focuses the GB field. → $impeccable clarify
3. **[P1] Destructive actions use native confirm() with no consequence statement.** Camera delete/reset/forget-face break the crafted world at the scariest moments and never say what survives. Fix: in-world confirmation dialog stating what is kept vs destroyed, coral action labeled. → $impeccable harden
4. **[P2] Global Settings exposes engine internals and undercuts the privacy promise.** Relabel in outcome terms; move User ID/Key under an explicit "Optional remote notifications" section; state the Face Detection ↔ Household dependency. → $impeccable clarify
5. **[P2] Live vs replay undistinguished; event icons unlabeled.** Identical video wells violate the design's own State Before Decoration rule; person/play/grid icons rely on hover. Fix: persistent LIVE/REPLAY tag bound to stream state; text labels for journal actions. → $impeccable clarify + polish
